## Assessment

The branch contains substantial crypto, storage, signing, daemon, broker and MCP
work. Its Stage 7 name does **not** mean Stages 1–7 are complete. The CLI exposes
only `version` and `mcp-server`. Runtime permits, capabilities, POST wallets and
`run` remain incomplete; no sandbox or hook crate exists. Windows daemon transport
is explicitly unsupported. The generated Linux release binary is dynamically
linked, so the one-static-binary goal remains unmet.

Existing CI omits the Python reference. More than 25 comparison tests return
success when `KV_PY_REF` is absent; a green run therefore does not prove those
comparisons executed. Some MCP comparisons send both frontends to the same Rust
daemon: matching unsupported replies prove frontend compatibility, not backend
feature completeness. One Stage 4 owner-endpoint mismatch is explicitly accepted.

Observed setup/test-runner issues:

1. `/var/tmp/kv-onboarding-tests` made generated Unix socket paths exceed Linux's
   length limit. `/var/tmp/k` fixed Stage 4 but still produced a 109-byte socket
   path for Stage 5's longer `python-home` fixture. `/var/tmp` reduced this to
   107 bytes with the five-digit PID in this run, and the API test passed. The
   test allocates its own random fixture directories there. Shorten fixture
   basenames in the parity-gate slice: another PID digit would exceed the limit
   again. Avoid transient platform `.git` placeholders under `/tmp` and `/workspace`.
2. The debug Stage 4 run times out waiting for a Rust daemon after Python upgrades
   the fixture key to production scrypt `(17,8,1)`. An isolated backtrace identifies
   `crates/kv-agent/tests/stage4_agent.rs:1105`; later mutex-poison failures are
   cascades. Optimized validation passed all six Stage 4 cases with the real KDF
   and unchanged deadlines; this supports the debug-performance diagnosis.
3. MCP fatal-frame comparison fails with Python 3.12 because Rust renders
   `limit (4300)` while Python renders `limit (4300 digits)`. The exact failing
   test passes with Python 3.10.22. The supported interpreter/error-text contract
   must be explicit in the future parity gate.

## Findings in implemented code

Detailed source evidence and acceptance tests are in
[implemented-path-findings.md](implemented-path-findings.md) and
[storage-crypto-findings.md](storage-crypto-findings.md).

| Finding | Evidence status | Required follow-up |
|---|---|---|
| Client IPC has no read/write exchange deadline | Source-confirmed; stalled-peer reproduction not run | Bounded exchange budget and stalled/partial-peer tests |
| Daemon uses per-read timeouts, retains completed worker handles and joins without a shutdown bound | Source-confirmed; resource/shutdown stress reproduction not run | Absolute request deadline, completed-worker cleanup, bounded shutdown tests |
| API audit path follows symlinks and changes target permissions | Source-confirmed; filesystem attack reproduction not run | Descriptor-pinned no-follow writes; ownership/type/identity and symlink/race tests |
| Shared audit log uses only a process-local mutex; caller discards audit errors | Source-confirmed; multi-process race reproduction not run | Cross-process chain serialization and visible failure policy |
| Environment-copy code clones secrets into ordinary, nonzeroizing strings/maps | Source-confirmed | Explicit secret lifetime types and error-path coverage |
| Storage/config lock files lack the Python descriptor/name identity recheck | Static race concern, not reproduced | Deterministic replacement-race tests and identity validation |
| Directory repair and atomic publication use pathname operations after checks | Static race concern, not reproduced | Verified directory descriptors and deterministic ancestor-replacement tests |
| Unicode numeric passphrase classification differs | Reproduced against both implementations | Exact Python-compatible digit classification and regression cases |

The reproduced passphrase cases are synthetic: Python accepts
`12345678901Ⅻ` and `12345678901½`; Rust rejects both as all-digit. Both reject
`123456789012`. Rust's `char::is_numeric` is broader than Python's `str.isdigit()`.
The external reproduction is retained in `/workspace/migration-audit/passphrase-probe.rs`
and `logs/passphrase-probe.log`.

Locked secret memory is also an unmet plan goal: zeroizing buffers exist, but
the tree has no implemented `mlock`/locked-buffer abstraction. This is separate
from the ordinary secret copies found in already-implemented paths.

## Proposed plan update and next slice

Keep the approved feature scope. Replace stage-number-based progress claims with
explicit gates: primitives, frontend compatibility, live authorization admission,
end-to-end operation, platform coverage, and release delivery. Preserve real KDFs,
assertions and security refusals; setup or CI must accommodate them.

Recommended first implementation slice, subject to the owner's next decision:
**make parity validation mandatory and reproducible**.

1. Pin/attest the Python source and runtime in CI; require a usable reference in
   a strict mode. An absent reference must fail, not return a passing test.
2. Record the expected parity inventory and completed results; distinguish
   platform exclusions, harness helper functions and accepted divergences.
3. Run the reverse Rust→Python crypto gate and suitable optimized integration
   tests with short isolated temporary paths. Shorten generated fixture names so
   sockets fit independently of PID width. Preserve all existing comparisons.
4. Check subprocess exits/deadlines; distinguish frontend-only comparisons from
   operations verified against both backends. Specify interpreter-dependent error
   text rather than accidentally using whichever Python is present.
5. Add regression coverage for the reproduced passphrase mismatch and decide its
   small compatibility correction as part of the agreed slice.

Next, address IPC/shutdown and audit-filesystem defects before extending daemon
authority. Then implement Stage 5b one-call permit admission/consumption, followed
by capabilities/POST wallets and Stage 6 sandbox execution. Successful admission,
replay/refusal, expiry, budget, revocation and no-network-side-effect tests must
precede claims of feature completion. Add secret-lifetime and filesystem-race
gates before marking storage/memory complete.

The owner has authorized plan review, but has not yet selected this implementation
slice. No feature implementation was started during this baseline audit.
